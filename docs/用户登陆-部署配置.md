# 用户登录部署配置与上线验收

2026-10-19。对应 [任务清单](用户登陆-tasks.md)。本文件不表示已经上线。

## 唯一的密钥

| 名称 | 内容 | 状态 |
| --- | --- | --- |
| `ADMIN_ACCESS_KEY` | 所有者一次性认领密钥，长度不限；越长越难猜，例如 `openssl rand -hex 24` 生成 | 待配置 |

在 Cloudflare Pages 项目的 Settings 中配置为加密 secret，或在终端交互输入：

```sh
npx wrangler pages secret put ADMIN_ACCESS_KEY --project-name macro-tracker
```

本地开发在启动时传入：`npx wrangler pages dev --binding ADMIN_ACCESS_KEY=<管理密钥>`。
未配置时，后台入口返回“管理入口尚未配置”。

## 所有者初始化

迁移 0007 把全部旧数据归属固定的 `owner` 账号，它一开始没有用户名和密码。

1. 打开 `/login`，点“注册新账号”。
2. 邀请码一栏填 `ADMIN_ACCESS_KEY`，再填自己的用户名和密码。
3. 注册成功后直接进入日记，看到的就是旧数据。

认领只能成功一次；之后再用管理密钥注册会提示邀请码无效。
不会让第一个注册者自动成为管理员，也不接受客户端传入角色。

所有者忘记密码时，在 D1 执行 `UPDATE accounts SET username = NULL WHERE id = 'owner'`，再按上面步骤重新认领。

## 邀请朋友

1. 使用所有者的用户名和密码登录后，直接打开 `/admin`。未登录时也可在 `/admin` 登录，无需额外管理密钥。
2. 在“邀请码管理”设定可使用次数，点“生成邀请码”，复制随机字母数字码发给朋友。
3. 朋友在注册页填写邀请码、用户名和密码，注册后进入角色创建。旧邀请链接仍可自动填入原邀请码。

新邀请码保存后可随时在后台查看、复制或停用。旧记录只有摘要，显示为旧邀请码，仍需使用原链接。

## 密码

- 用户名为 3 到 32 个字母、数字或下划线，不区分大小写；密码 4 到 128 个字符。
- 密码以“随机盐 + SHA-256”保存，不存明文。选择理由及安全边界见 [方案](用户登陆.md)。
- 用户在“角色”页的账号面板修改密码，需要输入当前密码；修改后其他设备的会话全部退出。
- 朋友忘记密码时，管理员在后台点“重置为临时密码”，把显示的临时密码发给对方。该用户的现有会话同时退出。

## 数据迁移与回退

生产执行前先停止业务写入并保留当前代码版本、完整 D1 SQL 备份和 D1 Time Travel 恢复点。业务 JSON 备份有用，但不替代数据库备份。

```sh
npx wrangler d1 export macro-tracker --remote --output /private/tmp/macro-tracker-before-accounts.sql
npx wrangler d1 time-travel info macro-tracker
```

上述备份含私人记录，应保存在本人控制的位置，不提交版本库。生产步骤须另行执行；本次没有运行这些远程命令。

1. 在独立本地副本应用 `0007_accounts.sql`。旧八张业务表全部归属 owner，字段及记录数不变。新用户完成角色创建后获得独立默认食物，不继承旧历史。
2. 配置 `ADMIN_ACCESS_KEY`。迁移与新版代码必须作为同一维护窗口的切换步骤，旧共享密钥版本与新表结构不兼容。
3. 在停止写入后执行生产迁移，再部署新版。按“所有者初始化”认领 owner，确认能看到完整旧存档，再验证后台入口。
4. 若失败，保持停止写入，恢复迁移前数据库备份或已记录的 Time Travel 点，同时回退匹配的旧代码。不要只回退前端，也不要对生产运行测试重建。恢复后核对旧数据及写入能力，再结束维护。
5. 上线后停止使用旧共享 API_KEY。新版业务接口不再接受该入口；旧标签页需要重新登录。

## 免费资源和现有限制

- 登录会话 7 天；后台按有效会话及管理员角色授权，退出或会话失效后必须重新登录。
- 登录每来源 15 分钟 20 次、每个用户名 15 分钟 10 次；注册每来源 15 分钟 10 次；后台密钥每来源 15 分钟 5 次。
- 普通写入每账号每分钟 120 次，导入每小时 5 次；后台写入每管理员每分钟 30 次；临时密码重置每目标账号每小时 3 次。
- 普通 JSON 最大 64 KiB；存档最大 8 MiB、50,000 条业务记录。导入只替换本人数据，所有删除及分块写入在同一事务提交。
- 邀请码最大使用次数 1 至 100；新邀请码仅在管理员列表返回，审计日志不记录原始码。上线前先应用 `0010_invitation_codes.sql`，再部署对应代码。
- 会话和业务读写消耗 D1 配额。打开页面每分钟检查一次全站规则，后台配置变更只提示刷新，避免丢失未保存输入。
- 管理列表最多展示 500 个用户、500 个邀请码和 100 条日志，适合朋友内测。
- Workers 线上 CPU、D1 扫描行数和真实容量尚未测量。用量接近限制时先停发邀请和检查热点，不自动升级付费。
